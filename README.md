# Game Marketing Learning

This repository contains the practical side of my game marketing studies.

## Source of truth

- **Notion** tracks the roadmap, learning status, reviews, and distilled knowledge.
- **GitHub** stores evidence of practice: research, exercises, experiments, datasets, project-specific analysis, and tools created when manual work proves they are useful.

Do not duplicate the knowledge base here. GitHub should contain work that can be inspected, challenged, reproduced, or reviewed.

## Repository structure

- `research/` — market, genre, competitor, comparable, audience, and other research.
- `exercises/` — focused learning exercises that are not tied to one real project.
- `projects/` — application of marketing knowledge to actual game concepts or games.
- `experiments/` — validation tests with hypotheses, methods, evidence, and decisions.
- `data/` — datasets used by research or experiments.
- `templates/` — reusable structures for analyses and exercises.
- `tools/` — automation created only after repeated manual work demonstrates a real need.

## Learning workflow

1. Learn a topic and track it in Notion.
2. Define a concrete practical task.
3. Do the work in this repository.
4. Submit/review the work as a coherent change when useful.
5. Record key conclusions and remaining gaps in Notion.
6. Apply the concept to a real project when possible.
7. Pass a later review before considering the topic mastered.

## Rule for tools

Do not build software merely because it could automate something.

A tool belongs here only when:

1. the task has already been performed manually enough to understand it;
2. a repeated bottleneck is visible;
3. automation will improve the research rather than replace thinking.

The goal of this repository is to learn game marketing, not to accidentally turn the course into a software-engineering side project.
